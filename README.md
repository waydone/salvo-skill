# salvo-skill

A Claude Code / agent skill for the **[Salvo](https://salvo.rs) Rust web framework** — target **1.1.2**. Install as a plugin (see below) or by symlinking into `~/.claude/skills/`.

Encodes Salvo's 1.1.2 API surface (project skeleton, routing, `#[handler]`/`#[craft]`, `Writer`/`Scribe`, core extractors, `JwtAuth`, middleware/`Depot`, OpenAPI 3.1/3.2, RFC 9457 problem details, WebSocket/SSE, static files & tus resumable uploads, response cache, OpenTelemetry semconv, multi-listener/Unix socket/HTTP3, error handling, testing, ops) as a lean **hub-and-spoke** skill: a compact `SKILL.md` + on-demand `references/*.md` (×13), plus `evals/`.

## Discipline baked in

- **Verify with Context7 before non-trivial code** — Salvo's API shifts across minor versions; the skill mandates a Context7 doc check for anything beyond a trivial `Router`.
- **edition 2024** for every new `Cargo.toml` — stated as a rule at the top of `SKILL.md`, in the frontmatter description and as an anti-pattern, because `edition = "2021"` keeps leaking out of training data (2024 is the current edition and what `cargo new` writes; Salvo 1.1's MSRV is **Rust 1.95**, current stable is **1.100**). Existing projects keep what they declare.
- `1.1.2` (from `1.1.1`) is a hardening patch with one **regression** — `#[endpoint(request_body(...))]` fails with `E0433: cannot find RefOr in salvo` through the `salvo` facade (workarounds in `references/openapi.md`) — and one field break (`Operation.request_body` is `Option<RefOr<RequestBody>>`). Behavior changes: encoded path separators → 400 before routing, request `Cache-Control` bypasses the response cache, `identity` honored in compression negotiation, upgraded connections hold `max_connections` permits.
- `1.1.1` (from `0.95.2`) is source-compatible for most app code — every 0.94 deprecated alias still compiles. What moves: typed extractors live in `salvo_core::extract` since 0.96 (`use salvo::extract::{...}`, no `oapi` needed); `full` includes `size-limiter` since 1.1.0; otel needs `opentelemetry = "0.33"` and emits semconv names (1.0); OpenAPI 3.2 docs emit `QUERY` routes (1.0); `Parameters(vec)` → `Parameters::from(vec)` (1.1); ACME HTTP-01 must serve :80 before `bind()` (1.1); secure-by-default changes (SVG/XML as attachment, multipart 128 parts/32 files → 413, CSRF on all unsafe methods, BasicAuth `Authorization`-only). `SKILL.md` opens with a "what changed 0.95.2 → 1.1.1" section.
- `0.95.2` (from `0.93.0`) is *almost* source-compatible — most changes are `#[deprecated]` warnings, the one hard break being the string-keyed `Depot::remove` signature (`remove::<T>("k")` → `remove(key) -> Option<Box<dyn Any>>`). `0.94.0` renamed the type-keyed `Depot` accessors (`obtain`→`get_typed`, `inject`→`insert_typed`, `scrape`→`remove_typed` — old names deprecated-but-compiling), split the JWT crypto backend (`jwt-auth` = jsonwebtoken `aws_lc_rs` default / `jwt-auth-ring` = RustCrypto), renamed `stop_forcible`→`stop_forceful` and `Response::stuff`→`render_with_status`, and raised MSRV to Rust 1.94. `SKILL.md` opens with a "what changed 0.93 → 0.95.2" section.

The v0.1.4 round (2026-08-17) is the **0.93 → 0.95.2 bump**. The v0.1.5 round (2026-11-09) is the **0.95.2 → 1.1.1 bump**. Every change was read from the `v0.95.2` vs `v1.1.1` tags of `salvo-rs/salvo` (crate sources, `Cargo.toml` features, the 1.0/1.1 CHANGELOG, the 0.96.0 release notes, official examples) — e.g. the extractor move into `salvo_core::extract`, `full` gaining `size-limiter` exactly at 1.1.0 (checked at every tag), the ACME `http01_challenge` source doc ("serve on port 80 before awaiting this listener's bind"), `Metrics::new()` binding to the provider installed at construction. Then a generated harness (now in `tools/verify/`, see below) turned **all 106 `rust` blocks** into modules of a real crate on `salvo = "=1.1.1"` (`full`) + Rust 1.99.1: 98 compile (normal **and** `cfg(test)`) with **0 errors, 0 warnings — no deprecated API used**; the 8 skipped are the sqlx/sea-orm database blocks (external ORMs, untouched apart from the extractor import) and two prose fragments. The harness surfaced **9 snippet bugs, all pre-existing from earlier rounds** (fixed): ops.md HTTP/3 used a nonexistent `RustlsListener::quinn` (now `QuinnListener::new(cfg.build_quinn_config()?, addr).join(tcp)` like the official `hello-h3`); testing.md used a nonexistent `TestClient` `.file(...)` (now a hand-built multipart body); `Session::insert(..)?` into `StatusError`; two `Json<NewUser>` DTOs missing `Serialize`; a rust-embed `match` with mismatched arms; missing `Filter` trait / `Message` imports; and three `use async_trait::async_trait;` lines that silently required an extra crate (the prelude re-exports it). **Runtime tests** (TestClient) confirmed the new behavior claims: 405 + `Allow`, SVG served as `attachment`, `QUERY` route only in a 3.2 doc, hand-built multipart → `FormFile`, `FormLimits` overflow → 413. That is an upstream regression (unfixed on `main` at `b695140a`, no issue filed as of 2026-11-13), not a snippet bug, so the skill now documents it with two workarounds that were each compiled in a scratch crate: inferring the body from a `JsonBody<T>` argument, and adding `salvo-oapi = "=1.1.2"` as a direct dependency. After the fix: **97 blocks compile with 0 errors, 0 warnings** on rustc 1.100.0 (8 skipped, 1 merged). Seven new `runtime` tests pin the 1.1.2 behavior claims: `%2F` / `%5C` in a path → 400 before any hoop runs, `CookieStore::host_prefixed()` → `__Host-salvo.csrf` + `Secure` over an HTTP hop, `max_concurrency(n).include_body(true)`, `Operation::request_body(Ref)` → `$ref` and `Link` → `operationId`, request `Cache-Control: no-cache` reaching the handler, `identity;q=1` beating `gzip;q=0.5`.

### Re-verifying (after editing the skill, or for the next Salvo bump)

```sh
tools/verify/check.sh
```

It regenerates `tools/verify/src/blocks/` from every ```` ```rust ```` block (one module each, `// file:line` header), runs `cargo check --all-targets` against the Salvo pinned in `tools/verify/Cargo.toml` — which must report **0 errors and 0 warnings**, so a deprecated API fails the check — and runs the `runtime` TestClient tests (405 + `Allow`, SVG attachment, `QUERY` in 3.2 docs, multipart → `FormFile`, `FormLimits` → 413, `jsonwebtoken` 11 unification, and the 1.1.2 set listed above). Blocks that need an external ORM or are prose fragments are skipped by content (`tools/verify/harness.json`); application names the snippets assume (`User`, `home`, `router`, `db::find`, …) live in `tools/verify/src/common.rs` — never Salvo API shims.

For a version bump: change the `salvo = "=x.y.z"` pin (and `opentelemetry` to the minor salvo-otel uses), run `check.sh`, then fix the skill — not the harness — until it's clean. Read the actual crate source for anything the CHANGELOG is vague about (clone `salvo-rs/salvo`, `git diff vOLD vNEW -- crates/`).

## Install

- **As a plugin (marketplace):** `/plugin marketplace add waydone/salvo-skill`, then `/plugin install salvo-skill@salvo-skill`.
- **Local (symlink):** from the repo root, `ln -sfn "$PWD/skills/salvo-skill" ~/.claude/skills/salvo-skill`.

## Updating after an edit

Bump `version` in `.claude-plugin/{plugin,marketplace}.json`, `git push`, then `claude plugin marketplace update salvo-skill && claude plugin update salvo-skill@salvo-skill`, and restart. Without a version bump, `plugin update` reports "already at latest" and won't pull the new content. If `marketplace update` fails with *"corrupted installLocation … expected a path inside <config dir>"* (the marketplace was registered from a different `CLAUDE_CONFIG_DIR`), run `claude plugin marketplace remove salvo-skill`, `claude plugin marketplace add waydone/salvo-skill`, `claude plugin install salvo-skill@salvo-skill`. Run the update once per Claude config dir you use.
